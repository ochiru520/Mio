# 澪的启动与开机自启动

## 日常使用

- 桌面应用：`D:\澪Agent\澪.exe`
- 开发环境入口：`http://127.0.0.1:8000/agent-app/`
- QQ 登录号和私聊白名单只保存在本机 `.env`，不写入文档。

启动器会做两件事：

1. 启动 FastAPI 后端和 Agent 界面。
2. 按设置决定是否启动 NapCat QQ 通道。

启动器可以重复运行。后端或 NapCat 已经在运行时，不会再启动第二份。

主动消息由 Agent 应用窗口的心跳控制：应用开着时约每 2 小时检查一次；应用关闭时暂停生成和扣费；再次打开后立即检查是否已经到期。QQ 在线时同步发送，QQ 离线时只在应用内显示。

启动器会在启动后等待最多 60 秒检查 QQ OneBot 连接。如果 `websocket_connections` 仍然是 `0`，并且 NapCat 生成了登录二维码，会自动打开：

`<NapCat目录>\cache\qrcode.png`

这时用手机 QQ 扫码登录机器人号即可。

## 日常维护原则

如果只是改了后端代码、提示词逻辑、联网逻辑或模型配置，优先只重启后端：

`工具\重启后端.bat`

这个脚本只重启 FastAPI，不关闭 NapCat/QQ，可以减少 QQ 登录态失效和重新扫码的概率。

不要把“停止澪”当成日常重启按钮。它是完整关机用的。

## 开机自启动

已创建当前用户的 Windows 开机启动快捷方式：

`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\启动澪.lnk`

开机自启动只在电脑进入系统并登录当前 Windows 用户后生效。

要保持 QQ 上的澪在线，需要：

- 电脑开着并已登录当前 Windows 用户。
- 电脑没有睡眠或休眠。
- 网络正常。
- NapCat 和后端没有被手动关闭。
- 中转站接口可用。
- QQ 登录态仍然有效；如果登录态失效，启动器会尽量自动打开二维码提醒扫码。

## 停止

项目内停止脚本：

`工具\停止澪.bat`

停止脚本会关闭本项目的 FastAPI 后端，以及设置中 `NAPCAT_DIR` 指向的 NapCat/QQ 进程。

注意：关闭 NapCat/QQ 后，下次启动可能触发 QQ 安全校验，需要重新扫码登录机器人号。这是 QQ/NapCat 登录态机制，不是模型或后端问题。

## QQ 不回复时的判断

先看：

优先打开 Agent 设置中的“QQ通道”，查看六项诊断；开发排查也可访问：

`http://127.0.0.1:8000/onebot/status`

- `websocket_connections = 1`：NapCat 已连到后端。
- `websocket_connections = 0`：NapCat 没连上，通常是 NapCat 未启动、QQ 未登录，或需要扫码。
- `event_debug.last_event_post_type = message`：后端收到了 QQ 消息事件。
- `event_debug.last_event_authorized = false`：收到了消息，但被白名单或群聊规则拦了。

如果 NapCat 目录下出现新的二维码：

`<NapCat目录>\cache\qrcode.png`

说明需要用手机 QQ 扫码登录机器人号。

## 卸载开机自启动

运行：

`工具\卸载开机自启动.ps1`

它会删除 Startup 文件夹和桌面的 `启动澪.lnk` 快捷方式，不会删除项目代码、数据库、日记或 NapCat。
