# Mio 代码结构与模块边界

本文描述 2026-09-19 已落地的职责拆分。它是维护导航，不表示所有共享状态和运行时编排都已完全解耦。

## 前端：界面、状态和业务操作分开

`澪Agent应用/src/App.vue` 保留根窗口组合、共享响应式状态、页面切换、生命周期以及页面上下文提供。现有 `components/` 仍负责页面和控件，`services/` 仍负责 API 请求。

`src/composables/` 按业务放置操作：

| 模块 | 负责的行为 |
|---|---|
| `useBootstrap` | 初始化和首页所需数据 |
| `useConversations`、`useChatInteraction` | 会话操作、消息提交和输入交互 |
| `useMessagePresentation`、`useAttachments` | 消息展示辅助、附件处理 |
| `useDiaries`、`useMemory`、`useTasks` | 日记、记忆与任务操作 |
| `useCompanion`、`usePetCall`、`useQq` | 桌宠界面操作、语音电话与 QQ 操作 |
| `useModelProviders`、`useSettings` | 模型供应商与分区设置的加载、保存 |
| `useDataPrivacy` | 数据备份、恢复和隐私操作 |
| `useDesktopNavigation` | 原生窗口导航 |
| `useUpdates` | 固定原生更新命令和可观察更新状态 |

组合函数通过显式依赖对象接入状态及跨域回调。可变普通变量使用 getter/setter，异步回调读取当前状态，不能把初始化时的值意外冻结。新业务不应继续直接加入 App.vue；优先添加到对应领域或新建小模块。现阶段 App.vue 仍集中一部分共享状态，可按后续实际变更继续分域。

测试应直接导入组合函数测试行为；不要再依赖“从 App.vue 文本截取函数并执行”的方式。更新客户端的并发状态、错误显示、命令边界等见 `src/updates.test.js`。

## 数据库：保留入口，按数据领域管理 SQL

`backend/app/db.py` 是兼容入口，保留连接、时间和领域实例装配。原有 `db.save_message` 等调用暂不改变，避免一次性重写所有服务。

`backend/app/repositories/` 分为 schema、memory、messages、costs、observations、daily_state、followups、agent_runs、diaries、autonomy、reviews。既有 `conversation_repository.py` 保留。

SQL、字段兼容和事务行为属于对应 repository。业务判断、网络调用和窗口控制不能进入 repository。新表结构应继续通过项目迁移机制管理，而不是让 API 路由临时改表。

连接和时钟通过显式回调注入；测试可使用临时数据库和可控时间。不要把用户正式数据库作为回归测试夹具。

## 桌宠：领域操作与进程编排分开

`backend/app/companion_service.py` 保留兼容函数、共享锁、进程与语音播放/合成的协调。时序敏感部分未在本轮重写。

`backend/app/companion/`：

| 模块 | 职责 |
|---|---|
| `configuration.py` | 配置迁移、标准化、音色选择 |
| `live2d_assets.py` | Live2D 资源发现、导入与验证 |
| `appearance.py` | 外观素材与尺寸处理 |
| `speech_text.py` | 语音文本清理、语言、情绪与韵律 |
| `audio_processing.py` | 音频解析、裁剪及信号处理 |
| `voice_packages.py` | 音色包导入导出与文件验证 |
| `training.py` | 音色训练与状态 |

领域服务不应在导入时启动后台线程、访问外网或写用户数据。跨域行为通过显式回调进入兼容层，不引入双份全局配置或双份播放队列。

## 更新器：与聊天模型彻底分离

桌面仓库 `desktop/updates/` 拆为清单验签、网络传输、更新状态机、独立事务助手和桌面适配。UI 只调用固定原生命令，不能传任意命令行或自行决定是否跳过验签。

下载成功、安装成功和新程序验证成功是不同状态。必须保留签名/摘要验证、原数据目录、维护备份和失败恢复；不要用模型回复或安装器退出码替代最终验证。

`desktop/publish_update.py` 负责构建通道与清单签名，不自动发布。更新密钥不属于模型配置，也不能写入 Git。
