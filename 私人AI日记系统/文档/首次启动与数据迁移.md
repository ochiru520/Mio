# 首次启动与数据迁移

## 首次启动

`0.5.0` 起，全新数据目录会先进入桌面应用内的首次启动向导。向导先检查 Windows、64 位运行环境、WebView2、数据目录、磁盘空间、SQLite 和内置后端，再说明本地与云端数据边界，并配置角色名字、用户称呼、联网搜索、主动联系、自动日记和 QQ 开关。

环境页还会只读检查云端模型、云端视觉、本地 Qwen2.5-VL、GPT-SoVITS、NapCat、Live2D、屏幕捕获和系统声音。可选能力缺失不会阻止进入应用，也不会在检查时自动联网、启动服务、加载模型或下载文件；用户可以稍后在对应设置页处理。

屏幕观察、系统声音监听、QQ 图片上传模型、自动回顾和周记默认关闭，需要用户在设置中单独开启。

已有用户不会被向导阻断。后端只在检测到用户消息、日记、非说明书记忆、结构化记忆、非默认角色属性或模型供应商配置时标记为旧用户；空数据库和自动生成的默认属性不算使用证据。

状态保存在：

```text
数据/首次启动.json
```

## 数据库迁移

数据库结构版本记录在 `schema_migrations` 表：

```text
version / name / applied_at
```

版本 1 表示 `0.5.0` 以前的现有结构基线。以后每个结构变化都必须通过独立迁移步骤执行。存在待执行迁移且数据库位于正式数据目录时，应用会先创建一份完整迁移前备份。

迁移状态可通过 `GET /api/migrations/status` 查看。迁移失败时应用不得继续使用半完成结构；修复后应从迁移前备份恢复或重新执行迁移。

## 完整备份与恢复

设置中的完整备份包含：

- SQLite 数据库、日记、记忆和状态。
- 运行设置、角色属性、模型供应商配置。
- 用户头像、角色头像、聊天背景、附件、照片和桌宠设置/素材。

完整备份不包含：

- `.env`、日志、缓存、临时画面、数据库 WAL/SHM。
- 备份目录自身。
- 外部音色训练目录和本地视觉模型目录。

每个 ZIP 带 `manifest.json`、格式版本、文件大小和 SHA-256。恢复前会自动创建回退备份；恢复拒绝路径穿越、未知格式、缺失文件和校验失败。恢复后必须重启应用。

模型供应商密钥使用 Windows DPAPI 加密。完整备份中的密文只适合同一 Windows 用户恢复；换电脑或更换 Windows 用户后需要重新填写 API Key。

## 跨版本和换机流程

1. 在旧安装的“设置 > 数据与隐私”创建并下载完整备份。
2. 安装新版本，不要手工复制正在使用的 SQLite 文件。
3. 在新安装中导入或放入完整备份，执行恢复并重启应用。
4. 检查对话、日记、记忆、角色和桌宠设置。
5. 换机时重新配置 API Key、QQ 登录和外部音色/视觉模型路径。
