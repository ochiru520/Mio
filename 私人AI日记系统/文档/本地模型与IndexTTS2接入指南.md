# 本地模型与 IndexTTS2 接入指南

适用：Mio 0.4.2。使用前需要自行准备相应的本地模型或 IndexTTS2 环境。

## 本地大模型

在 Mio 设置的模型供应商中新增“本地模型”，选择 LM Studio 或 Ollama。地址可以修改，API Key 可以留空；如果服务开启了认证，则填写服务实际要求的 Key。

| 服务 | 默认 OpenAI 兼容地址 | 启动前提 |
| --- | --- | --- |
| LM Studio | `http://127.0.0.1:1234/v1` | 加载模型并启动 Local Server |
| Ollama | `http://127.0.0.1:11434/v1` | 启动 Ollama 且已准备模型 |

使用“获取模型”读取实际服务的模型列表，选择并保存，再在聊天或 Agent 的模型选择中使用。模型 ID 必须以服务返回值为准。可以连接受信任局域网的服务；不要把示例中的 `127.0.0.1` 用作另一台电脑的地址。

普通聊天可直接使用本地模型。Agent 还依赖模型本身的工具调用、参数遵循和上下文能力。“模型支持工具调用”是供自动选择模型使用的能力标记，不会额外开启电脑执行权限；勾选也不能让不支持工具的模型获得该能力。

对于兼容接口，Mio 仅在服务明确拒绝相应参数时移除 `stream_options` 或退回非流式。已收到文本或工具分片后不会因为断流重新发送整轮。`response.failed`、不完整响应、达到长度上限和上游错误不会假报成功。检查报错时仍需对照具体模型与服务版本。

本机/字面内网 IP 的模型请求绕过应用代理。云端供应商仍按原有鉴权要求处理。

## 本地 IndexTTS2

设置 → 角色语音，选择 **IndexTTS2（独立本地服务）**。先在 IndexTTS 自己的环境准备好源码、IndexTTS-2 权重和依赖模型；Mio 不会自动下载这些内容，也不把 torch 装进自己的环境。

在 PowerShell 中启动配套桥接脚本，替换下面的路径：

```powershell
& 'D:/AI/index-tts/.venv/Scripts/python.exe' 'D:/Mio/_internal/agent_scripts/indextts2_adapter.py' --repo 'D:/AI/index-tts' --model-dir 'D:/AI/index-tts/checkpoints_2'
```

源码运行时，脚本位于 `澪Agent应用/scripts/indextts2_adapter.py`。安装在其他目录时，把 `D:/Mio` 换成实际程序目录。

等待脚本显示就绪，再在 Mio 中填 `http://127.0.0.1:11996`，上传参考音频或填写本机音频完整路径，然后保存并试听。参考音频通过 HTTP 传输，服务运行在另一台电脑时不需要共享同一个音频路径。

这使用 Mio 配套的 `mio-indextts2-v1` 桥接协议。**官方 Gradio 的 7860 页面不能直接当作这个服务地址**，也不支持把 IndexTTS-2.5 当成 IndexTTS-2。此模式合成完整 PCM WAV 后播放，首次播放速度取决于硬件，不是流式首音。

更多启动参数、限制、错误排查见程序 `_internal/agent_scripts/indextts2_adapter.md`。独立服务由用户启动和关闭，Mio 的语音开关不会安装或代管这个进程。

## 角色记忆与设置提示

- 新增自动记忆和上下文摘要读取当前角色名称、对用户的称呼。历史记忆原文不会批量改写；群聊不使用私人用户称呼。
- 默认未配置的可选人设 Markdown 显示“未配置（可选）”；每轮实际角色来源显示为“当前角色卡（每轮读取）”。手动指定却丢失的文档继续显示真实错误。
- “改造 Mio”首次使用会展开源码绑定，需要分别选择“私人AI日记系统”和“澪Agent应用”的源码目录。安装目录不能替代源码；没配置好前不能创建改造任务。
- 校验错误、嵌套服务错误和构建版本改为可读显示，避免 `[object Object]`。

## 验证范围

本地 HTTP 测试覆盖模型发现、请求、SSE/JSON、工具调用与失败不重复执行，以及 IndexTTS2 参考音频传输、配置保存、WAV 和错误处理。它们是协议验证，不代表已经在用户的 Qwen/IndexTTS2 模型上完成推理与音质验收。实际推理表现与音质需要在准备好模型的环境中试用。
